# 哔哩哔哩首页知乎风改造（油猴脚本）

把 bilibili.com 首页的推荐流改造成「知乎信息流」样式：

- **标题** = 视频标题（18px 加粗，hover 变蓝）
- **作者** = UP 主名称（可点进空间），单独一行 `UP主：xxx`
- **简介块**：前面带「简介」小徽章，正文 = 视频简介（无简介时依次退化为「标签」徽章 + 视频标签）；三者都没有就显示灰斜体提示「（该 UP 主没有填写简介）」
- **字幕块**：简介下面另起一块，同样带「字幕」小徽章；字幕按 B 站**原生时间轴一条一行**，行首标出时间点（`00:12`），点时间点直接跳到视频的该秒；只先露前几条，点 `展开字幕` 就在原地接着往下排（没有面板、不内部滚动），展开后内联的 `收起` 滚出视口时，右下角会浮出一个固定的 `收起字幕` 胶囊按钮（点它＝收起并滚回字幕开头）；没抓到字幕时显示「字幕 暂无字幕」提示，不会让用户以为脚本没生效
- 点 `阅读全文 ⌄` **就地展开**全文，不跳转、不开新标签；展开后变 `收起`，收起后滚动条还原到展开前的位置（内容一缩，不还原就会跟看页面跳到别的卡片）
- 简介本来就没被截断时，不显示「阅读全文」
- 封面图全部移除（推荐流卡片、顶部大轮播、直播/番剧楼层小卡、信息流里的直播卡、骨架占位）
- 卡片底部一行「👍 点赞 · 💬 评论 · ⭐ 收藏」（图标 + 数量，1.2万/亿 自动缩写）；**点「点赞」就地给视频点赞**（图标变红实心、数字 +1，再点取消），**点「评论」弹窗里直接渲染评论区**（头像、正文、表情、点赞数、子回复、滚动分页、热门/最新切换），**「收藏」只显示数字、不可点**（不在卡片里假装能收藏）；Esc / 点遮罩 / ✕ 关闭
- 居中单列 760px、白底卡片 + 1px 分割线、浅灰页面底色

## 实现要点

- **样式**：`document-start` 注入 `<style data-bili-no-cover>`，用 CSS 隐藏封面、重排卡片，动态节点自动生效。
- **结构**：在标题 `<h3>` 后插入 `.z-answer`，里面依次是 `.z-byline`（`UP主：xxx`）、`.z-desc-row`（`简介` 徽章 + 正文 + `阅读全文`）、`.z-sub-slot`（`字幕` 块）；原 `__info--bottom` 由 CSS 隐藏。
- **卡片节奏**：B 站每张卡外面还套了一层 `.feed-card`，所以每张卡都是自己父节点的 `:last-child`；分割线不能靠 `:last-child` 判断，改为在容器层级去掉最后一张。外层 wrapper 自带的 24~40px 间距也统一压平，卡片之间只留 1px 分割线。
- **非投稿卡**：番剧 / 活动 / 广告 / 直播卡链接里没有 `BV` 号，封面藏掉后只会剩一块空白，直接标 `.z-skip` 不显示。
- **简介数据**：`/x/web-interface/view?bvid=` 取 `desc`（空则退 `dynamic`，再空则 `/x/tag/archive/tags` 取标签）。
  - 同一个响应里的 `stat.like / stat.reply / stat.favorite` 直接用于底部操作栏，不额外请求
  - 结果缓存在 `localStorage`（键 `zbili:desc:v4`，TTL 7 天）
  - 首屏外卡片由 `IntersectionObserver` 懒加载，队列 2 并发 + 错峰 200ms
  - 命中风控（-352 / -412）自动暂停 30 秒，期间卡片退化为占位文字
- **DOM 兜底**：`MutationObserver` 监听新增节点，Vue 重渲染后自动补回 `.z-answer`。

## 字幕（视频文稿）

- **接口链路**：`view` 拿 `aid` / `cid` → `/x/player/wbi/v2` 拿字幕列表 → `aisubtitle.hdslb.com` 拿字幕 JSON。
  - `player/v2`（不带 wbi 签名）现在返回的是**随机视频**的字幕地址，必须用 WBI 签名（`w_rid` / `wts`，密钥来自 `/x/web-interface/nav` 的 `wbi_img`），脚本里内置了纯 JS 的 MD5。
  - 字幕文件在 `aisubtitle.hdslb.com`，页面内 `fetch` 会被 CORS 拦，所以用 `GM_xmlhttpRequest`（已在头部声明 `@grant` / `@connect`）。
  - 需要**登录状态**：未登录时 B 站不返回 AI 字幕，卡片就不会出现字幕块。
- **排版**：直接用 B 站原生时间轴 —— `body[]` 里一条字幕就是卡片里的一行，前面标时间点。
  - 实测 AI 文稿一条平均 ~10 字（最长 20 字）、条目首尾相接（`from[i] == to[i-1]`，没有停顿间隙）、全篇无标点，所以卡片里会显得碎（6 分钟视频约 235 行），但断点一定落在语音边界上，不会切在半句 / 词中间。
  - 不想这么碎就把 `subtitleByTimeline` 改 `false`，退回按 60 字 / 1.5 秒停顿合并的段落式排版。
  - 单视频最多保留 1200 条 / 6 万字（长直播文稿会非常多），并过滤 `♪ 音乐 ♪` 这类占位、相邻重复条目。
- **时间点跳转**：行首的 `00:12` 是链接，指向 `https://www.bilibili.com/video/BVxxxx?t=秒`，点了在新标签页打开并从那一秒开始播（`?t=` 定位已实测生效：`t=14` → `video.currentTime === 14`）。
- **展示**：不管有没有简介，字幕都是独立的一块（「字幕」徽章 + 虚线上分割线），一条一行、行首是时间点。
  - 默认只露前 `subtitlePreviewLines` 条，末尾跟 `展开字幕`；点了就把剩下的条目接在后面继续往下排（没有黑底面板，也没有滚动区域），再点「收起」回到前几条。
  - **长字幕的「收起」**：展开后内联「收起」会被顶到几百行下面，所以字幕块还在视口里、而内联「收起」已经滚出视口时，右下角浮出一个深色胶囊「收起字幕 ⌃」。
    - 位置不是贴屏幕右边，而是**跟卡片正文对齐**：`right: max(22px, calc((100% - 卡片宽) / 2 + 卡片 padding 22px))`，即右边缘正好压在卡片正文右边缘上（1280 视口下右边缘在 `x = 991`，卡片白框右边缘 `1013`，差 22px = 卡片 padding）；视口窄于卡片时退化成 `22px`，刚好也对齐卡片 padding。纵向 `bottom: calc(22px + env(safe-area-inset-bottom))`。
    - 点赞 toast 从 `bottom: 46px` 上提到 `78px`（同样带 safety-area），不会和胶囊按钮叠在一起。
    - 点它等于点内联那个；不管是点内联「收起」还是悬浮胶囊，收起后都调 `restoreScroll(展开时的 window.scrollY)` 把滚动条放回原位（`behavior:'smooth'`，目标值 clamp 到新的最大滚动高度），不会因为几十行内容突然消失而跳到别的卡片。
    - 内联「收起」重新进入视口 / 字幕块整体滚出视口 → 胶囊自动淡出（`IntersectionObserver` 同时观察字幕块和内联按钮，`threshold: 0`）。
    - 同一时刻只服务最后展开的那一个字幕块（再展开别的卡片，悬浮按钮就归它）；`allowCollapse: false` 时不会出现。
  - 展开时才把剩余行建 DOM（3 条 → 200+ 条的卡片不会一上来就铺满节点）。
  - 没抓到（视频没有文稿 / 未登录 / 请求失败）→ `字幕 暂无字幕` 灰斜体提示，鼠标悬停有原因说明。
  - 简介也没有、标签也没有 → 「简介」块显示 `fallbackDesc` 灰斜体提示，「字幕」块显示 `暂无字幕`，两张牌都告诉用户为什么卡片这么短。
- **缓存**：字幕按 `[[开始秒数, 正文], ...]` 存 `localStorage`（键 `zbili:sub:v2`，TTL 3 天，最多 30 条），不写进简介缓存，避免把 localStorage 撑爆；旧的 `zbili:sub:v1`（无时间轴的长文本）启动时直接清掉。
  - 简介缓存（`zbili:desc:v4`）序列化时会剔掉 `sub`（体积大）和 `subTried`（只是内存里「别重复抓同一个视频」的标记）；`subTried` 被写进缓存的话，下次打开这些视频会直接显示「暂无字幕」。
- **流量**：`always` 模式下每张卡都要多拉一个字幕文件（长视频几百 KB），移动网络建议改 `noDesc` 或 `off`。

## 点赞 / 收藏（卡片底部操作栏）

- **收藏**：卡片里没法完成收藏（要选收藏夹），所以默认做成**不可点的静态数字**：`CONFIG.favClickable = false` 时去掉 `<a>` 的 `href` / `target`，加 `z-static`（`cursor: default`、hover 不变蓝），`title` 写「收藏数（收藏请进视频页）」，点它什么都不会发生。改 `favClickable: true` 就恢复成点一下跳视频页。

### 点赞（点一下就点上了）

卡片底部的「点赞」不再跳视频页，点一下就直接给视频点赞：

- **接口**：`POST https://api.bilibili.com/x/web-interface/archive/like`，表单参数 `bvid` / `like` / `csrf`
  - `like=1` 点赞、`like=2` 取消赞；`csrf` 就是 Cookie 里的 `bili_jct`（没这个值说明没登录）
  - **不需要 WBI 签名**（已登录状态下实测：点赞 → `has/like` 变 1，取消 → 变 0）
  - 返回码：`0` 成功、`-101` 未登录、`-111` csrf 过期、`65006` 重复点赞、`65004` 取消点赞失败（其实没赞过）、`-352`/`-412` 风控
- **已点赞状态**：鼠标扫过点赞按钮时查一次 `/x/web-interface/archive/has/like?bvid=`，已赞就直接显示红心（只查一次，不给每张卡白打请求）
  - 这个接口只反映「近期」是否点过赞，半年前点过的会返回 0；本地状态和服务器不一致时，以 `65006` / `65004` 的返回为准就地纠正
- **数字**：B 站的 `stat.like` 里**已经包含自己那一票**，所以「发现已点赞」只变色不加 1，只有本次真点上去才 +1（取消才 -1）
- **交互**：图标 `fill: currentColor` 变红实心、`aria-pressed` 跟着变、底部飘一句轻提示（已点赞 / 已取消点赞 / 请先登录 / 被风控）；连点有 600ms 冷却，避免打太快被风控
- **不改逻辑只跳页**：把 `CONFIG.likeInPlace` 改 `false` 就回到旧行为

## 评论弹窗

卡片底部的「评论」不跳页，弹一个 860×84vh 的对话框，里面**直接调评论接口原生渲染**（早期版本用 iframe 拉整个视频页，首屏要 3.5s，现在是 0.2s 左右）：

- **接口**：`/x/v2/reply?oid=<aid>&type=1&pn=N&ps=20&sort=1|0`
  - `sort=1` 按点赞（热门）/ `sort=0` 按时间（最新），弹窗右上角可切
  - `pn` 翻页，滚到底自动加载下一页；返回条数 < 20 即到底
  - 这个接口**不需要 WBI 签名**（`/x/v2/reply/wbi/main` 不带签名直接 -403）
  - `aid` 由 `/x/web-interface/view?bvid=` 取（每张卡本来就要请求一次，浏览器有缓存）
- **子回复**：`/x/v2/reply/reply?oid&type=1&root=<rpid>&ps=10&pn=N`。回复框里先渲染接口自带的 3 条预览，点「展开更多回复（还有 N 条）」再翻页，按 rpid 去重
- **渲染**：头像 + 昵称（UP 主挂粉色 `UP` 标）+ 正文 + 相对时间 + 点赞数
  - 表情 `content.emote` 替换成 `i0.hdslb.com` 小图（`height: 20px`）
  - `@某人` 按 `content.members` 高亮成蓝色
  - 图片评论 `content.pictures` 最多显示 3 张
  - 正文先 `escapeHtml` 再插表情图，不把原文丢给 innerHTML
  - 头像 / 表情地址统一把 `http://` 和 `//` 都升级成 `https://`（不升级的话后台一堆 Mixed Content 警告）
- **置顶**：第一页会先把 `top` / `top_replies` 插到最前（rpid 去重），浅蓝底
- **关闭**：✕ / Esc / 点遮罩空白处；打开时锁 `html{overflow:hidden}`，关掉还原
- **实测**：点开 → 首条评论 **225ms**（iframe 方案 3.5s），首屏 20 条、滚到底 40 条、子回复 3→10→可继续展开、热门 / 最新切换正常、控制台 0 error
## 已知情况

- 页面底部部分灰块是 B 站自己的占位骨架（未装脚本也存在），脚本会隐藏它们。
- 控制台可能出现来自旧版本残留在子 iframe 的报错，刷新/重启浏览器后消失，不影响页面。
- 点赞需要**已登录**（`bili_jct` Cookie）；未登录点「点赞」只提示「请先登录 B 站再点赞」，不发请求。
- `has/like` 刚点完的几秒内可能还是旧值（B 站缓存），脚本只用它在点击前查状态，不影响按钮的即时反馈。
